# boilersync-rs

`boilersync` scaffolds projects from templates and keeps templates alive as projects evolve: `init` a project from a template, `pull` template updates into it later, `diff` to see how it diverged, and `push` proven improvements back into the template.

This repository is the Rust implementation of boilersync. It is a successor to the Python `boilersync` package and keeps the same command surface, `template.json` and `.boilersync` formats, template syntax (`$${...}` Jinja delimiters, `NAME_*` path placeholders, `.starter` and `.boilersync` file extensions) and the `~/.boilersync/templates` cache layout, so existing templates and projects keep working. Values render exactly as the Python implementation rendered them (for example booleans as `True` / `False`), so a project generated by either implementation shows no spurious drift in `diff`.

## Layout

| Crate | Purpose |
| --- | --- |
| `crates/boilersync-core` | Library: template sources and inheritance, rendering, variable collection, project metadata, every command |
| `crates/boilersync-cli` | The `boilersync` binary (clap) |

## Installation

```bash
cargo install --git https://github.com/montaguegabe/boilersync-rs boilersync-cli
```

Or build from a checkout:

```bash
cargo build --release
# binary at target/release/boilersync
```

`git` must be on your `PATH`. `gh` is used for template-configured GitHub repository creation and to infer `github_user`; GitHub Desktop's `github` command is used by `boilersync push`.

## Quick start

```bash
# 1) Clone a template source into your local cache
boilersync templates init https://github.com/your-org/your-templates.git

# 2) Initialize a project from a source-qualified template ref
boilersync init your-org/your-templates#python/service-template

# Well-defaulted templates can be initialized without prompts
mkdir my-app-workspace
cd my-app-workspace
boilersync init your-org/your-templates#python/service-template --non-interactive

# 3) Pull template updates into the current project when needed
boilersync pull

# 4) Check project divergence from the current template
boilersync diff

# 5) Create a reviewable pull proposal without mutating the project
boilersync pull-proposal create

# 6) Push committed project changes back into the template source
boilersync push
```

## Commands

| Command | Purpose |
| --- | --- |
| `boilersync init TEMPLATE_REF [--var K=V]... [--option K=V]... [--non-interactive] [--monorepo]` | Create a project from a template in an empty directory, then run its hooks, GitHub repo creation and child templates |
| `boilersync check-pull` | Compare the recorded template commit with the cached template repo HEAD (exit 1 when due) |
| `boilersync diff [--stat\|--name-status\|--patch\|--json] [--include-starter] [--children\|--recursive] [--output PATH]` | Render the template with the saved variables and show how the project diverged |
| `boilersync pull [TEMPLATE_REF] [--include-starter] [--no-children]` | Apply template updates to an existing project (clean git tree required) |
| `boilersync pull-proposal create [--include-starter] [--children] [--workspace-dir DIR] [--json]` | Run the pull in a scratch copy and report the proposed changes |
| `boilersync pull-proposal apply-file PROPOSAL_DIR PATH` | Copy one proposed file into the project |
| `boilersync pull-proposal apply-patch PATCH` | Apply selected hunks with `git apply` |
| `boilersync push [--add-files FILE]...` | Review committed project changes in GitHub Desktop and copy them back to the owning templates |
| `boilersync templates init [REPO_URL] [--no-input]` | Clone a template source repository into the cache |
| `boilersync templates list [--json]` | List cached templates |
| `boilersync templates sources [--json]` | Show cached source checkouts and duplicate remotes |
| `boilersync templates details TEMPLATE_REF [--json]` | Show the effective inputs of a template after inheritance |
| `boilersync skills install [--dev] [--source PATH] [--skill NAME]...` | Install the BoilerSync agent skills for Codex and Claude Code |

Every command accepts `--verbose`.

## Template references

- `org/repo#path/to/template`
- `https://github.com/org/repo#path/to/template`
- `https://github.com/org/repo.git#path/to/template`

GitHub is the only supported host. Source-qualified refs clone (if missing) into `${BOILERSYNC_TEMPLATE_DIR:-~/.boilersync/templates}/<org>/<repo>`. `BOILERSYNC_ROOT_DIR` overrides the project root lookup (the nearest directory with a `.boilersync` file).
